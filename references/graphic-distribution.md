# 图文优先与多形态分发

## 三卡默认

小绿书、小红书和公众号图片消息默认 `3` 张，信息确有独立价值时扩展，最多 `5` 张：

1. `钩子与价值`：真实对象/场景、具体标题、读者为什么现在关心。
2. `机制与证据`：产品如何工作、真实用例/参数/截图/来源。
3. `购买或行动判断`：适合谁、边界、可保存的清单或下一步。

七个规划问题（钩子、痛点、例子、机制、边界、判断、行动）应合并进 3 张，不得机械变成 7 张。只有每张都增加新事实、决策规则、证据或问题时才扩张。

使用 `templates/graphic_post.md` 保存：最终标题、3 个备选、每卡文案、视觉任务、证据来源、裁切比例、平台配文和边界。

## 视觉与证据

- 第一张在 3 秒内让读者看懂对象、场景和收益，不从芯片/模型参数起讲。
- 每张只有一个主要信息，常规正文约 `20-60` 个汉字，字号大、对比强、留白足。
- 至少一张承担证据任务：官方实物图、真实截图、命令/输出、参数、来源片段或带日期的商业信号。
- 真实产品图优先；生成图只能做封面、概念或机制说明，不得改变产品外观或当作证据。
- 生成图默认无文字、Logo、水印和伪界面；需要准确文字时用排版工具后期添加。
- 同组图片保持主体、材质、色调和光线一致，但通过景别、场景和信息层级推进，不重复库存照。

## 平台适配

- 小红书/小绿书使用 `3:4` 或 `4:5`，配文简洁，包含平台原生话题和短作者身份，不出现“在看、星标”等微信专属话术。
- 公众号图片消息使用 `md2wechat create_image_post` / `newspic` 或当前已验证路径，不把图片消息塞进长文转换接口。
- 公众号长文使用 `publishing-archive.md` 的固定结尾；其它平台各自适配标题、正文、媒体、披露和 CTA。
- 同步、填表或打开编辑器不等于发布。每个平台独立记录 `未开始 / 已准备 / 已预填 / 已审核 / 已发布 / 失败 / 阻断`。

## Hook + Action + Identity

- `Hook`：第一卡和配文开头立即说明理由、对象与结果。
- `Action`：只选择一个主要动作；收藏对应参数/清单，评论对应可回答的问题，转发对应能替读者表达的判断，关注对应可信的系列下一篇。
- `Identity`：短内容使用一次简洁作者线；不重复个人介绍或强迫关注。

## 一题多资产

证据足够时，从同一事实底稿派生：

- 3 卡图文。
- 30-60 秒视频号脚本（一项承诺、一个场景、一个结果）。
- 80-120 字朋友圈文案。
- 一条 X 文案。
- 3 个封面/标题方向。
- 只有需要多来源、架构取舍、客户语境或长期参考价值时，才扩成长文。

派生素材共享事实和边界，但开头、节奏和 CTA 必须适应平台。未获授权时只准备本地资产，不上传、不预填、不发布。
